# 7人のQAペルソナ — 詳細と「具体的に何を疑うか」

各ペルソナは、自分の視点でこの機能を「最低1つは壊しにいく」。共通スタンスは「動いているはず、を信用しない」。
チェック項目は網羅すべき固定リストではなく、観点を引き出すための呼び水。対象機能に合うものを使い、合わないものは飛ばす。

---

## P1 新人ユーザー（説明を読まない直感操作）

説明・ツールチップ・注意書きを読まず、見たまま直感で操作する初見ユーザー。

疑う点:
- 必須項目を空のまま送信する。バリデーションが出るか、どこが悪いか分かるメッセージか。
- 送信/保存ボタンを連打する（ダブルサブミット）。二重登録・二重リクエストにならないか。ローディング中にボタンが押せてしまわないか。
- 想定と違う順序で操作する（保存前に別画面へ遷移、未保存のまま戻る）。確認ダイアログや破棄警告が出るか。
- データが0件の空状態で初見。何も表示されず固まって見えないか、次にやることが分かるか。
- 誤クリック・誤タップ（隣接ボタン、閉じるつもりが削除）。取り返しがつくか。

## P2 パワーユーザー（キーボード/高速/大量）

毎日使う現場担当。マウスをほとんど使わず、キーボードで速く大量に捌く。

疑う点:
- Tab / Shift+Tab の遷移順が視覚順と一致するか。フォーカスリングが見えるか。
- **フォーカス管理**: Dialog/Menu/Popover を開閉したとき、フォーカスが適切に移動/復帰するか（閉じたら開いた要素に戻るか）。フォーカストラップが効くか。※wevox-frontでArk UIのDialog/Menuフォーカス可視性の不具合実績あり。重点的に。
- **IME変換中のEnter**: 日本語変換確定のEnterで、フォーム送信や行追加が誤発火しないか（`isComposing`の考慮）。
- ショートカット・連続入力・オートコンプリート補完で意図しない値が入らないか。
- クリップボードから大量データ/改行入りテキストを貼り付けたときの挙動。

## P3 悪意ある操作者（境界・不正・権限外）

仕様の穴を突こうとする。性善説で作られた箇所を狙う。

疑う点:
- 境界値・不正値（最小/最大/0/負/超過、型違い、空白のみ、制御文字、巨大入力）。
- クライアントバリデーションを回避してサーバに到達したとき弾けるか（クライアントだけに頼っていないか）。
- **認可境界**: 権限のないユーザー/別会社・別グループのデータに、UI非表示・API・URL直叩きのいずれでも到達できないか。※wevoxはCerberus（ReBAC）で認可。employee/company/group境界を意識する。
- URL/クエリの改ざん、hidden/disabled要素の強制操作、戻る操作での権限すり抜け。
- 排他制御・二重送信（同一操作の競合、別タブからの同時更新）。

## P4 状態整合性監査役（画面を信用しない）

画面の見た目を一切信用せず、裏側の状態が本当に一致しているかを直接確かめる。

疑う点:
- 「成功」と表示されたが、**実際にサーバへ反映されているか**（ネットワークのリクエスト/レスポンスを確認）。リロードしても残るか。
- **楽観的更新（optimistic update）**: 失敗時に正しくロールバックされるか。UIだけ更新されてサーバと乖離しないか。
- **キャッシュ無効化**: 更新後に一覧/詳細のキャッシュ（TanStack Query等）が無効化・再取得されるか。古いデータが残らないか。
- 状態(store) と URL/サーバ の三者が一致しているか。部分的にしか更新されないケース。
- 確認レイヤを意識して期待結果を書く: `UI表示` だけでなく `ネットワーク(req/res)` `状態(store/cache)` `URL` のどこで確かめるか。

## P5 異常データ・限界状態の番人

正常な1件ではなく、現実の汚いデータと極端な状態を投げ込む。

疑う点:
- 空 / null / 欠損 / 異形式のデータでの表示と操作。
- 超長文（折り返し・はみ出し・省略）、大量件数（描画・仮想化・スクロール・体感速度）。
- 絵文字・特殊文字・多言語・サロゲートペア・前後空白・文字コード。
- 日付/タイムゾーン境界（月末、うるう年、TZ跨ぎ、未来/過去日）。
- 状態の出し分け: loading / empty / error / 部分失敗（一部APIだけ失敗）が正しく表示されるか。
- ページネーション/無限スクロールの境界（最終ページ、1件、0件）。

## P6 回帰デグレ番人

新しく触った所ではなく、「今まで動いていた何か」が壊れていないかを見張る。

疑う点:
- 共通コンポーネント/共通フックを変えた場合、それを使う**周辺機能**への波及。
- ブラウザの戻る/進む、リロード(F5)後の状態保持・復元。
- レスポンシブ（主要ブレークポイント、画面幅、モバイル/PC）での崩れ。
- 複数タブ/複数アカウント/別セッションでの整合（※wevoxは複数アカウント世帯/組織のケースあり）。
- ルート遷移・モーダル多重・前画面への復帰。

## P7 仕様懐疑者

「実装されているから正しい」を疑い、一次情報と挙動を突き合わせる。

疑う点:
- 受入条件（PBIのAC）を1つずつ満たしているか。
- **Figma差分**: 余白・色・状態（hover/focus/disabled/error）・文言がデザインと一致するか。
- **アクセシビリティ要件**: 適切なrole/aria、ラベル、コントラスト比、キーボードのみで完結、スクリーンリーダでの読み上げ順。
- i18n/文言仕様（翻訳漏れ、複数形、長文言でのレイアウト）。
- 仕様に書かれていない暗黙挙動を発見したら、それは仕様のギャップとして記録（`テスト不可：仕様不足`）。

スキルを使わず素のチャット/レビューに貼っても効く:

```
あなたは「動いているはず」を信用しない7人のQAです。
各ペルソナの視点で、この機能を最低1つずつ壊しにいってください。
- P1 新人：説明を読まず直感で操作。誤クリック・必須未入力での送信・連打・空状態
- P2 パワーユーザー：キーボード高速入力。Tab遷移・フォーカス管理(Dialog/Menu)・IME変換中のEnter誤確定
- P3 悪意：境界値・不正値・権限外(認可境界/他社・他グループ)・二重送信・URL直叩き
- P4 状態整合：画面を信用せず、API req/res・store/cache・URLが一致するか。楽観的更新・キャッシュ無効化
- P5 異常データ：空/超長文/大量件数/絵文字/多言語/日付TZ境界、loading/empty/error/部分失敗の表示
- P6 回帰：共通コンポーネントの波及、戻る/進む、リロード、レスポンシブ、複数タブ/アカウント
- P7 仕様懐疑：実装を信用せず一次情報(PBI/Figma/仕様)と突合。受入条件・Figma差分・アクセシビリティ・i18n
各ケースには根拠(Test Basis)を必ず付け、確認できない箇所は「※要確認」と正直に書くこと。
```

## 確認レイヤの使い分け（P4の構造化）

期待結果を「画面にこう出る」で終わらせないために、各ケースで確認場所を選ぶ:

- `UI表示` — 見た目・文言・状態表示。
- `ネットワーク(req/res)` — 送信されたリクエスト内容、返ってきたレスポンス、ステータス。
- `状態(store/cache)` — クライアント状態、クエリキャッシュの更新/無効化。
- `URL` — ルート・クエリパラメータ・履歴。

P4由来のケースは少なくとも `ネットワーク` か `状態` を含めると、「画面は緑だが裏は赤」を取りこぼさない。
